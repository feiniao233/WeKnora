# 带宽拥塞诊断规程

- 场景 ID：`bandwidth-congestion`
- SOP 版本：`1.0.0`

## 适用范围与必要输入

适用于交换机、路由器、防火墙、服务器网卡等接口的带宽压力与拥塞迹象诊断。判断以接口容量、连续指标样本、丢包或丢弃以及拓扑影响为准；不同设备的计数器和采样周期可能不同。

必须有可唯一定位的告警标识。`resolve_alarm` 返回后必须取得告警时间、资产/接口、方向或触发指标；无法取得接口容量时只报告原始流量，不能计算或声称利用率。

## 固定调用顺序

1. `resolve_alarm`：传入用户提供的告警 ID 或告警键；记录权威告警 ID、资产、接口、方向、触发指标、发生/恢复时间和观察区间。
2. `get_asset_context`：传入已解析资产/接口；关注接口容量、管理状态、计数器单位、计数器方向和指标采样语义。
3. `get_topology_context`：传入已解析资产/接口；关注对端接口、下游资产和是否存在同期影响。无拓扑结果不代表影响仅限当前接口。
4. `query_operational_evidence`：传入已解析资产/接口及系统允许观察窗口；查询 `metrics`、`alarms`、`logs`。关注连续入/出流量、利用率、丢包、丢弃、错误、状态变化和恢复时间，保留单位与采样时间。
5. 知识检索：仅在已有指标证据后检索绑定知识库；关键词为“接口利用率”、“丢包”、“丢弃”、“队列拥塞”、“接口计数器”、“流量突发”，并以实际设备类型补充关键词。

工具错误或空结果都是缺失信息；除无权威告警外，继续完成其余可执行查询。不得主动采样、刷新设备状态、抓包、限速或调整接口配置。

## 停止条件

- 无权威告警，或没有可核验的接口/指标时间范围：停止，结论为 `未知`。
- 缺少容量、采样周期、单位或方向时，停止利用率和跨设备阈值推断；可保留原始观测并给出 `未知` 或 `存在歧义`。
- 仅单个峰值且无丢弃、业务影响或连续样本：不得推断持续拥塞。

## 候选原因与证据

### 持续容量压力

支持：多个连续样本接近已知接口容量，并出现丢包、丢弃、时延或下游影响。反对：仅有短时峰值，或流量长期远低于容量。

### 短时流量突发

支持：流量只在少量样本达到峰值后快速恢复，且没有持续丢弃或影响。反对：峰值跨多个连续采样窗口，或丢弃持续存在。

### 链路质量下降

支持：流量低于已知容量，但错误、丢包或状态变化明显增加。反对：错误稳定且拥塞与高利用率、持续丢弃同步。不能把所有影响归因于带宽不足。

### 测量信息不足

支持：容量、采样周期、方向或单位缺失，或指标无法与告警时间对齐。反对：完整连续指标和容量证据足以支持其他候选原因。

## 人工验证与报告

人工验证：核对接口协商速率、指标单位和采样周期；查看既有性能监控中的峰值、丢弃与相关业务影响；按已有变更流程评估容量或流量治理。本规程不执行这些动作。

报告遵循 `SKILL.md` 的统一报告格式；摘要标明场景 ID、SOP 版本、权威告警 ID、观察窗口和接口容量是否已知。候选原因同时列出支持与反对证据 ID/时间戳；原始指标、单位、采样时间、空结果和工具错误必须保留。
