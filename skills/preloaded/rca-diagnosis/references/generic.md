# 通用未匹配场景诊断规程

- 场景 ID：`generic`
- SOP 版本：`1.1.0`

## 适用范围与必要输入

仅在 `network-interface-down`、`ip-conflict` 和 `bandwidth-congestion` 均不匹配或无法唯一选择时使用。不得用本规程把未知问题强行归入试点场景。

必须有可唯一定位的告警标识。主流程完成 `resolve_alarm` 后，记录权威告警 ID、发生时间、可用资产字段和原始告警文本；无权威告警时停止。

## 证据查询

- 前置条件：复用主流程中已解析的告警，不得再次调用 `resolve_alarm`。
- `get_asset_context`、`get_topology_context` 和 `query_operational_evidence` 可在同一轮发起，均只传入已解析告警中工具接受的可用字段。输入不足的查询跳过并记入缺失信息，其余查询继续。
- `get_asset_context`：只用资产标识、名称、地址以及类型和区域摘要核对告警对象。无资产字段时记录缺失，不补造目标。
- `get_topology_context`：只用资产所在节点、拓扑资产数等摘要作为粗粒度背景，不推断相邻节点或具体依赖。无结果不是健康证明。
- `query_operational_evidence`：传入已解析告警组成的 `alarm`，以与告警直接相关的 `alarms`、`logs`、`metrics` 为 `kinds`，不因未知场景扩大范围。观察窗口由服务端固定为告警前后 30 分钟；指标仅按实际返回的接口名称或索引、入出方向值、接口速率和入出丢弃解释。
- 知识检索可选。仅在需要解释设备语义、指标含义、阈值、策略或历史案例以区分候选原因时检索；使用告警的中性现象词、设备类型和可核验字段，不使用客户资产名称或猜测的故障类型，也不为填充引用而检索。

工具错误和空结果都是缺失信息。不得传入接口、争议 IP 或自定义时间窗口等未声明参数；不得调用试点外的操作工具、探测网络、刷新状态或修改设备和源数据。

## 停止条件与候选判断

- 无权威告警，或没有诊断告警、日志、指标或根因分析证据：结论为 `未知` 并停止。
- 只有一组跨来源、带时间戳的证据支持某个中性现象时，可列为 `疑似`；不得提升为确认或使用 `场景匹配`、`存在歧义`。
- 证据无法支持一个中性现象、资产范围或时间关系时：结论为 `未知` 并停止继续推断。

可报告的候选仅限于“存在待核验的设备/链路状态异常”“存在待核验的地址归属异常”“存在待核验的性能异常”或“证据不足”。支持证据必须是告警、日志、指标或拓扑中的可追溯观察；反对证据是同时间窗内相反观察或缺少必要关联。不得给出具体根因、设备操作建议或未被证据支持的场景名称。

## 人工验证与报告

人工验证：在既有告警、资产和运维系统中核对时间线、受影响范围与原始记录；如需进一步操作，按现有运维流程另行执行。本规程不执行这些动作。

报告遵循 `SKILL.md` 的统一报告格式；摘要标明 `generic`、SOP 版本、权威告警 ID 和观察时间窗。结论只允许 `疑似` 或 `未知`，并在“缺失信息”中列出未匹配原因、空结果和工具错误。
