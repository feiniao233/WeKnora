# 通用未匹配场景诊断规程

- 场景 ID：`generic`
- SOP 版本：`1.0.0`

## 适用范围与必要输入

仅在 `network-interface-down`、`ip-conflict` 和 `bandwidth-congestion` 均不匹配或无法唯一选择时使用。不得用本规程把未知问题强行归入试点场景。

必须有可唯一定位的告警标识。`resolve_alarm` 返回后记录权威告警 ID、发生时间、资产/接口（如有）、状态和原始告警文本；无权威告警时停止。

## 固定调用顺序

1. `resolve_alarm`：传入用户提供的告警 ID 或告警键；确认上述基础事实。
2. `get_asset_context`：传入已解析资产或接口（如有）；关注资产身份、设备类型、管理状态和相关标识。无资产标识时记录缺失，不补造目标。
3. `get_topology_context`：传入已解析资产或接口（如有）；关注相邻节点、已知依赖和影响范围。无结果不是健康证明。
4. `query_operational_evidence`：传入已解析的目标和系统允许时间窗；查询与告警直接相关的 `alarms`、`logs`、`metrics`，不因未知场景扩大范围。
5. 知识检索：仅在已有运行证据后检索绑定知识库；使用告警的中性现象词、设备类型和可核验字段，不使用客户资产名称或猜测的故障类型。

工具错误和空结果都是缺失信息。不得调用试点外的操作工具、探测网络、刷新状态或修改任何数据。

## 停止条件与候选判断

- 无权威告警，或没有诊断告警、日志、指标或 RCA 证据：结论为 `unknown` 并停止。
- 只有一组跨来源、带时间戳的证据支持某个中性现象时，可列为 `suspected`；不得提升为确认或使用 `scene_matched`、`ambiguous`。
- 证据无法支持一个中性现象、资产范围或时间关系时：结论为 `unknown` 并停止继续推断。

可报告的候选仅限于“存在待核验的设备/链路状态异常”“存在待核验的地址归属异常”“存在待核验的性能异常”或“证据不足”。支持证据必须是告警、日志、指标或拓扑中的可追溯观察；反对证据是同时间窗内相反观察或缺少必要关联。不得给出具体根因、设备操作建议或未被证据支持的场景名称。

## 人工验证与报告

人工验证：在既有告警、资产和运维系统中核对时间线、受影响范围与原始记录；如需进一步操作，按现有运维流程另行执行。本规程不执行这些动作。

报告遵循 `SKILL.md` 的统一报告格式；摘要标明 `generic`、SOP 版本、权威告警 ID 和观察时间窗。结论只允许 `suspected` 或 `unknown`，并在“缺失信息”中列出未匹配原因、空结果和工具错误。
