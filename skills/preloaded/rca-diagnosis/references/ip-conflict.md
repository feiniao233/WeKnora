# IP 地址冲突诊断规程

## 适用范围

本规程用于不同设备、接口或地址分配记录在重叠时间内声明同一 IP 地址的只读诊断。厂商告警名称只作为线索，判断以权威告警、资产身份、地址归属变化和同一时间窗口内的运行证据为准。

## 输入要求

- 可唯一定位的告警标识
- 涉及的 IP 地址与告警时间
- 报告冲突的资产或接口标识

无法取得权威告警记录或争议地址时停止分析，不根据用户描述补造冲突对象。

## 诊断步骤

1. 回查告警，确认争议地址、报告资产、首次发生时间和当前状态。
2. 查询资产及拓扑上下文，列出系统中所有已知地址声明者，并保持资产 ID、接口、MAC 和主机名字段彼此独立。
3. 在系统限定的时间窗口内查询配置变更、DHCP 分配、ARP 归属变化、重复地址检测及设备上下线证据。
4. 比较每个声明者的有效时间，判断是否存在两个不同资产身份的重叠声明。
5. 查阅地址分配策略和设备手册，形成需要运维人员现场确认的验证步骤。

## 候选原因与证据

### 活跃的重复地址

支持证据是两个不同资产身份在重叠时间内声明同一地址，并有告警、日志或地址归属变化相互印证。单条 ARP 记录不足以确认。

### 地址重新分配

支持证据是配置或 DHCP 记录显示地址从旧资产转移到新资产，且两个声明时间不重叠。这属于归属变化，不应误报为持续冲突。

### 资产台账或采集延迟

支持证据是库存记录存在重复，但运行日志只显示一个有效声明者，或旧记录在设备下线后未及时清理。

### 冲突对象无法归属

运行证据能够确认地址冲突，但第二个资产身份缺失。此时只能报告未知声明者，不得从厂商名称或拓扑位置猜测设备。

## 结论等级

- `suspected`：重叠声明证据支持一个主要候选原因，等待人工确认。
- `ambiguous`：地址重新分配、台账延迟和活跃冲突无法由现有时间证据区分。
- `unknown`：缺少争议地址、资产身份或运行证据。

自动分析不得输出“已确认根因”。报告必须保留资产身份、证据标识、时间戳、支持与反对证据以及缺失信息。
