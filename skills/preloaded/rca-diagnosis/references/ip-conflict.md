# IP 地址冲突诊断规程

- 场景 ID：`ip-conflict`
- SOP 版本：`1.0.0`

## 适用范围与必要输入

适用于不同设备、接口或地址分配记录在重叠时间内声明同一 IP 地址的只读诊断。厂商告警名称只是线索，判断以权威告警、资产身份、地址归属变化和运行证据为准。

必须有可唯一定位的告警标识。`resolve_alarm` 返回后必须取得争议 IP、告警时间和至少一个报告资产或接口；缺少争议 IP 时停止，不根据描述补造冲突对象。

## 固定调用顺序

1. `resolve_alarm`：传入用户提供的告警 ID 或告警键；记录权威告警 ID、争议 IP、报告资产/接口、首次发生时间和当前状态。
2. `get_asset_context`：传入已解析的报告资产/接口；关注资产身份、主机名、接口、MAC、已登记 IP 和地址归属有效时间。不同字段必须保持独立，不把相同名称视作同一资产。
3. `get_topology_context`：传入已解析的报告资产/接口；关注同网段、相邻设备和可见的二层关联。无拓扑结果不能排除冲突。
4. `query_operational_evidence`：传入争议 IP、已解析资产/接口及系统允许时间窗；查询 `alarms`、`logs`、`metrics`。关注配置变更、DHCP 分配、ARP 归属变化、重复地址检测和设备上下线；指标无关时不据此扩大查询。
5. 知识检索：仅在已有运行证据后检索绑定知识库；关键词为“IP 冲突”、“重复地址检测”、“DHCP 地址分配”、“ARP 地址变更”、“地址分配策略”，并以实际设备类型补充关键词。

工具错误或空结果都是缺失信息；除权威告警或争议 IP 缺失外，继续完成其余可执行查询。不得扫描网段、发送探测包、修改 DHCP 或改变设备配置。

## 停止条件

- 无权威告警或无争议 IP：停止，结论为 `未知`。
- 无法获得第二个声明者、有效时间或任何运行证据：停止继续推断，结论为 `未知`。
- 已证实地址归属异常但无法区分活跃冲突、重新分配或台账延迟：结论为 `存在歧义`。

## 候选原因与证据

### 活跃的重复地址

支持：两个不同资产身份在重叠时间声明同一 IP，且告警、日志或 ARP 归属变化互相印证。反对：只有单条 ARP 记录，或两个声明有效期不重叠。

### 地址重新分配

支持：配置或 DHCP 记录显示地址由旧资产转移到新资产，且声明时间不重叠。反对：两个身份在同一时间活跃声明地址。

### 资产台账或采集延迟

支持：库存记录重复，但运行日志只显示一个有效声明者，或旧记录在设备下线后未清理。反对：运行证据显示两个身份同时使用该地址。

### 冲突对象无法归属

支持：运行证据确认地址冲突，但第二个资产身份缺失。反对：没有重复声明或运行证据仅来自静态台账。不得从厂商名称、MAC 前缀或拓扑位置猜测对象。

## 人工验证与报告

人工验证：在既有网管或地址管理系统核对两个声明者的地址归属、DHCP/配置变更和现场接入关系；必要时按既有变更流程处理。本规程不执行这些动作。

报告遵循 `SKILL.md` 的统一报告格式；摘要标明场景 ID、SOP 版本、权威告警 ID、争议 IP 和观察时间窗。候选原因同时列出支持与反对证据 ID/时间戳；资产身份缺失、空结果和工具错误写入“缺失信息”。
