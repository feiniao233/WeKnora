# IP 地址冲突诊断规程

- 场景 ID：`ip-conflict`
- SOP 版本：`1.1.0`

## 适用范围与必要输入

适用于不同设备、接口或地址分配记录在重叠时间内声明同一 IP 地址的只读诊断。厂商告警名称只是线索，判断以权威告警、资产身份、地址归属变化和运行证据为准。

必须有可唯一定位的告警标识。主流程完成 `resolve_alarm` 后，争议 IP 必须来自权威告警字段或原始告警内容；缺少争议 IP 时停止，不根据用户描述补造冲突对象。

## 证据查询

- 前置条件：复用主流程中已解析的告警，不得再次调用 `resolve_alarm`。
- `get_asset_context`、`get_topology_context` 和 `query_operational_evidence` 可在同一轮发起，均只传入已解析告警中工具接受的可用字段。不得把从告警内容识别出的争议 IP 作为额外工具参数。输入不足的查询跳过并记入缺失信息，其余查询继续。
- `get_asset_context`：只用资产标识、名称、地址以及类型和区域摘要核对报告资产；这些字段必须保持独立，不把相同名称视作同一资产，也不推断 MAC 或地址归属有效期。
- `get_topology_context`：只用资产所在节点、拓扑资产数等摘要作为粗粒度背景；无结果不能排除冲突，不推断同网段、相邻设备或二层关联。
- `query_operational_evidence`：传入已解析告警组成的 `alarm`，以 `alarms`、`logs` 为 `kinds`；仅当返回的告警或日志内容实际包含相关记录时，才观察配置变更、DHCP 分配、ARP 归属变化、重复地址检测或设备上下线。观察窗口由服务端固定为告警前后 30 分钟。
- 知识检索可选。仅在需要解释设备语义、地址策略或历史案例以区分候选原因时检索，可使用“IP 冲突”“重复地址检测”“DHCP 地址分配”“ARP 地址变更”“地址分配策略”等中性词并补充实际设备类型。

工具错误或空结果都是缺失信息。不得扫描网段、发送探测包、修改 DHCP 或改变设备配置。

## 停止条件

- 无权威告警或无争议 IP：停止，结论为 `未知`。
- 无法获得第二个声明者、有效时间或任何运行证据：停止继续推断，结论为 `未知`。
- 已证实地址归属异常但无法区分活跃冲突、重新分配或台账延迟：结论为 `存在歧义`。

## 候选原因与证据

### 活跃的重复地址

支持：两个不同资产身份在重叠时间声明同一 IP，且告警、日志或 ARP 归属变化互相印证。反对：只有单条 ARP 记录，或两个声明有效期不重叠。

### 地址重新分配

支持：配置或 DHCP 记录显示地址由旧资产转移到新资产，且声明时间不重叠。反对：两个身份在同一时间活跃声明地址。

### 资产台账或采集延迟

支持：库存记录重复，但运行日志只显示一个有效声明者，或旧记录在设备下线后未清理。反对：运行证据显示两个身份同时使用该地址。

### 冲突对象无法归属

支持：运行证据确认地址冲突，但第二个资产身份缺失。反对：没有重复声明或运行证据仅来自静态台账。不得从厂商名称、MAC 前缀或拓扑位置猜测对象。

## 人工验证与报告

人工验证：在既有网管或地址管理系统核对两个声明者的地址归属、DHCP/配置变更和现场接入关系；必要时按既有变更流程处理。本规程不执行这些动作。

报告遵循 `SKILL.md` 的统一报告格式；摘要标明告警名称、资产名称或 IP、发生时间、场景 ID、SOP 版本、争议 IP 和观察时间窗。候选原因同时列出支持与反对证据的可读描述和时间戳；资产身份缺失、空结果和工具错误写入“缺失信息”。
